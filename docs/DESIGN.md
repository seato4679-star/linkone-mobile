# LinkOneのデザイン刷新

2026-09-22。Appleをイメージしたデザインへの変更依頼を受け、[Appleの製品サイト](https://www.apple.com/jp/iphone/)を参考として確認した。LinkOne独自の名称・文章・CSSで構成し、Appleのロゴや製品画像は使用していない。

## 見た目の方針

- 白・シルバー・黒をベースに、操作できる場所には青を使う。
- トップは中央揃えの大きな見出しと、CSSで描く端末を主役にする。
- LPは黒背景と大きな価格で、トップとは異なるキャンペーンの存在感を出す。
- カードは薄い境界線と大きめの角丸。影は端末などの立体表現に限定する。
- フォームと管理画面も同じ配色・書体・ボタンで統一する。警告・エラー・対応状態の意味を持つ色は残す。

## 変更したファイルと理由

`src/app/design.css`に新しい配色・文字・余白・部品表現をまとめ、`layout.tsx`で`globals.css`の後に読み込む。既存のレイアウト・入力状態・エラー表示を残し、見た目の変更箇所を教材として探しやすくするため。`page.tsx`では主見出しと2つのセクション見出しを短くした。依存ライブラリの追加はない。

```css
:root { --ink: #1d1d1f; }
.button { border-radius: 999px; }
@media (max-width: 480px) {
  .hero-copy h1 { font-size: 36px; }
}
```

1行目は、サイト全体から参照するCSS変数（名前付きの値）に文字色を設定する。2行目は共通ボタンの角を大きく丸める。3〜5行目はメディアクエリ（画面の条件に応じてCSSを切り替える指定）で、小さい画面の見出しを36pxにする。

既存部品との互換性のため、`--green`という変数名も現状は残し、値を青にしている。色を変更する際は`design.css`の`:root`から読む。CSSのカスケードとは、同じ要素への複数の指定から、詳細度や記述順で適用値が決まる仕組み。新デザインを変更するときは、このファイルを優先して編集する。

## データの流れ

CSSはブラウザでの表示を変える。申込処理の流れは `React → fetch → Next.js API → 保存 → 完了 → 管理` のまま。料金計算・API・DB・認証の処理は今回変更していない。

## 確認

- 本番build、lint、TypeScriptが成功。HTTPスモークテスト50項目合格。
- トップ・LP・料金・試算・申込・完了（受付情報なし）・privacy・管理一覧の8画面を375 / 768 / 1024 / 1440pxで確認。実際のinnerWidthも照合し、32パターンすべて文書全体の横はみ出しなし。
- PCのトップ・LP・管理一覧、スマホのトップ、768pxの申込フォームを画像で確認。
- スマホの主見出しの不自然な折り返しを調整して再確認。検証中のブラウザConsoleにerror / warnなし。
- Supabase実接続とVercel公開は今回の変更に含まない。公開準備はPRE_RELEASE_QA.mdのチェックリストを参照。

手元では `npm run build` → `npm run start` で起動し、トップとLPの違い、画面幅を縮めたときの見出し・カード、試算画面の選択色を確認する。すでにサーバーが起動中の場合は二重に起動せず、ブラウザを再読み込みする。

PRE_RELEASE_QA.mdの配色・コントラスト値は刷新前の検証記録。本ファイルは今回のデザイン変更分の記録であり、過去の配色に関する数値を新デザインの測定値として扱わない。
